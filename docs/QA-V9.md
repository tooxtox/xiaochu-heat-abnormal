## 七、浏览器引擎

`--engine browser` 曾报 "Same-time rendering produced different pixels"（t = 63.0 / 71.9）。
根因是人物缓存画布**内容**在同刻两次渲染间不同：缓存键不含尺寸（画布被 `canvas.width` 改写后内容被清空而 key 不变），
且 `ctx.reset()` 只重置状态、**不清空画布**。

修法：缓存键改为 `${key}@${width}x${height}` 且创建后不再改尺寸；所有复用画布的 `reset()` 显式 `clearRect`；
浏览器导出在确定性检查前做一次热身渲染。

复验：`node tools/render.mjs --engine browser --start 62.5 --duration 3 --fps 60 --output work/browser-probe-v9c.mp4`
成功输出 180 帧（1920×1080 / 60fps / 含 AAC），确定性闸门通过。

**残留限制**：浏览器引擎的冷路径画布与热路径仍有亚像素差异（首帧与后续帧不同），
已通过导出前热身规避；**原生引擎（实际出片所用）不受影响**。

## 八、已知限制

1. 歌词入字为图形编排，未声明逐字演唱对齐；行级时间由同版音频校准（偏移 2.186875 s）。
2. 人物仍是 7 处有限局部拆层，头颈、手指与完整身体新动作未绑定。
3. 闪光筛查是启发式，不是光敏性癫痫安全认证。
4. 目视复核为抽样，不是逐帧人工观看；全部 14553 帧只做了程序解码与指标筛查。
5. 浏览器引擎冷路径画布与热路径存在亚像素差异（见第七节）。
6. 内建分段闪光启发式在 214.85–215.85 s 记了 1 个窗口（8 次大面积像素变化）。
   该指标统计的是"大面积像素变了多少"，不区分撕裂运动与频闪；
   逐帧的权威筛查 `check_flash.py` 在同一段只找到 2 次亮度方向变化，`flagged_windows` 为空。
   成片对应画面为高对比红天下的一次高潮撕裂，属设计内的崩坏表现。
