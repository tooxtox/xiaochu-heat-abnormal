# V11：疾走与崩坏剪辑

全曲成片：`export/LAST-SIGNAL-1080p60-v11.mp4`，实际 **1920×1080 / 60fps / 14553 帧 / 242.55 秒 / AAC**，264274247 B。成片解码、音轨、接缝、分段画面对照与抽样目视均已完成，证据见 `docs/QA-V11.md` 和 `export/v11-artifact-qa.json`。

V11 把高能段从约 5 秒的长镜改为多种景别交替的快切：世界、全身、人物、眼睛、手部与抽象空间互相打断。保留 63 个原叙事镜头作为父镜头，生成 **156 个镜头、93 个新增实测 onset 切点**；人物到场、终端展开和场景进程继续沿用父镜头年龄，避免每次切镜重新开始。

## 节奏与空间

- 第一处 68–90 秒加速，79.514 秒后更密；第二处 189–231.69 秒逐级加速。199.448–204.732 秒与 212.569 秒后是主要冲刺段。
- 一般快镜约 0.65–1.30 秒，局部短跑接近 0.326 秒；实际完整快镜最短 **0.30 秒**。连续最多 4 个不超过 0.45 秒的短镜，之后安排至少约 1 秒的停留。快切多为硬切，少量斜向快门最多 4 帧。
- 画面加入短促推近、横移、滚转和外缘速度线；主阅读层维持原父镜头的平稳机位。快切眼睛／手部的亮背景上增加深色字缘，帮助白色主字保持边界。
- 两处重档崩坏新增斜向图像快门、三角碎片和同刻放大回声，分别在打击后约 0.16／0.23／0.19 秒收束。第一处空间冲击系数为 0.58；最终高潮逐渐增加，爆点之间恢复主构图。
- 七组重复歌词仍使用中档：intensity 上限 0.50、tier 上限 3；不加入新增空间破碎通道。间奏、较安静的段落与结尾继续保留长镜。

切点从本地音源的 1181 个 onset 候选中选择，93 个新增切点有 57 个来自较强 onset。特征分辨率为 20Hz；自动节拍候选 **91.941／180.89 BPM 未经人工确认**，只用候选间隔引导编辑密度，不声明歌曲改变了 BPM 或拍号。

## 输入与重建

输入仍为 `assets/audio/song.m4a`、`data/audio_features.json`、`data/cues.json`、`data/lyrics.json`、`data/lyric_direction.json` 和 `data/shots.json`。126 行日文、126 行中文及 264 条歌词导演记录保持时间不变。主音源来自用户选定的 B 站 25 时 2DMV，保留源时间零点；逐字入场是图形编排，未验证逐字演唱时间。

`tools/build_rhythm_edit.mjs` 从当前镜头中保存的 `baseShot` 恢复原 63 个父镜头，再选择实测 onset 重建剪辑；不需要历史 `work/` 基线。已验证重跑所得 `data/shots.json` 字节哈希相同。下面第一条命令会重写镜头数据，通常只在正式渲染前运行：

```powershell
node tools/build_rhythm_edit.mjs
node tools/render.mjs --width 1920 --height 1080 --fps 60 --jobs 3 --encoder-threads 3 --chunk-duration 12 --crf 18 --preset fast --output export/LAST-SIGNAL-1080p60-v11.mp4
```

`--encoder-threads` 限制各 FFmpeg 编码器线程，避免并行导出挤占内存；没有更改 CRF、预设或分辨率。渲染器继续保留首帧缓冲、同刻确定性、分段接缝与源 AAC 包哈希检查。可用 `--lyrics PATH`、`--lyric-direction PATH` 指定替代歌词输入，原生分段与浏览器后备会共用相同数据。

验收记录见 `docs/QA-V11.md`。`tools/check_rhythm_edit.mjs` 的旧版对照需要冻结的 V10 基线目录，可通过第三个位置参数指定；正常渲染和镜头重建不依赖该目录。
