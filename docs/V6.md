# 第六版：崩坏后期

记录日期：2026-10-23。第六版在第五版的画面之上增加一层贯穿全片的"崩坏"后期处理，
重点加在重复段与高潮段。

## 定位

第五版把126 组日中歌词编成场景叙事，画面克制、干净。这一版不推翻它，而是在
"信号开始损坏"的地方让画面主动崩坏：重复段（ERASE / PERSIST）像坏掉的循环磁带，
高潮段（CORE / REALITY）像系统被烧穿。

崩坏全部是**纯时间驱动**的后期：每个参数都由歌曲时间和已有的鼓点表推出，
不读前一帧、不用随机数、不看系统时钟。同一时刻反复渲染必须得到同一张图。

## 分区强度

| 场景 | 标签 | 强度 | 说明 |
|---|---|---|---|
| 1 | INIT | 0 | 不崩坏 |
| 2 | DEAD VARIABLES | 0 | 观察段保持干净 |
| 3 | FEAR / VASCULAR CURRENT | .22 | 只有轻的信号抖动 |
| 4 | ERASE / PERSIST | .78 | **重复段**，重度崩坏 |
| 5 | BLACK STAR | .58 | 吸收段，中度崩坏；ARRIVAL 额外 +.30 |
| 6 | BROKEN VOICE | .46 | 副歌重复，中度崩坏 |
| 7 | MEMORY | 0 | 记忆段不崩坏 |
| 8 | CORE / HEAT ABNORMAL | 1.00 | **高潮**，最强 |
| 9 | REALITY / REFUSAL | .95 | **高潮**，强 |
| 10 / 11 | SIGNAL / SHUTDOWN | 0 | 不崩坏 |

段落首尾各有 0.6 秒 / 0.4 秒的进出包络，所以崩坏是"长进来"的，不是硬切。

## 打击点

崩坏强度不连续跳变，而是由真实鼓点（`data/shots.json` 的 `loopOnsets`，414 个）触发。
每个鼓点按哈希分成 4 级：

- 1 级：轻微脉冲，只抬一下颤抖与分离（约占 64% 鼓点）。
- 2 级：出现行位移撕裂与黑白信号条。
- 3 级：描线闪白、黑白拉到高位、同步滚动条（哈希命中 44%）。
- 4 级：局部负片、像素化、数据块（哈希命中 22%）。

间距约束让极端打击单独占位：4 级至少间隔 0.90 秒，3 级至少 0.48 秒，
2 级至少 0.20 秒。因此崩坏落在节奏上，不会变成连续噪声。
实测重复段每段 3–5 次 3 级打击，高潮段约 22 次 3 级、8 次 4 级。

段落底噪乘以打击包络得到最终强度：`intensity = 段落强度 × (0.72 + 0.95 × 打击包络)`。
底噪负责"持续崩坏"，打击负责"爆点"，两者相乘所以强打击能顶到上限 1.0。

## 特效清单

| 特效 | 实现 | 触发 |
|---|---|---|
| RGB 分离 | 红通道右移、蓝通道左移后叠加在原帧上，原帧保持锐利与白平衡 | 常驻，幅度随强度 |
| 颤抖 | 整帧位移 + 轻微旋转 + 微量缩放 | 常驻 |
| 黑白 | `color` 混合把色相饱和度换成中性灰，保留明度 | 底噪 + 3 级打击 |
| 描线闪白 | 水平/垂直边缘差 → 自乘一次压掉弱边缘 → 中性灰 → 叠加 | 3 级以上 |
| 黑白色块 | 横向信号条 / 纵向信号条 / 空心框三种 | 2 级以上 |
| 行位移撕裂 | 逐条横向错切，采样始终取自干净原帧 | 2 级以上 |
| 同步滚动条 | 一块内容竖向绕回 | 3 级以上 |
| 数据块 | 局部低分辨率重采样，保留 28% 原画面 | 3 级以上 |
| 局部负片 | 小面积方块反相 | 4 级 |
| 像素化 | 整帧降到极低分辨率再放大 | 4 级 |
| 噪点雪花 | 确定性散点 | 常驻 |
| 重影 | 整帧偏移叠加 | 常驻 |

顺序：几何崩坏 → 色块 → 黑白 → 描线闪白 → RGB 分离 → 负片 → 重影 → 噪点 → 颤抖。

### 两种分离方案的区别

最初的做法是抽出 R/G/B 三通道各自错位后与原帧交叉淡化。强度提上去之后发现两个问题：
绿色通道留在原位会在主体正中留下一层绿重影，整帧偏向三重彩虹；把绿通道压到 0.55 又会让
白主体变成品红。最终改成**只把红通道右移、蓝通道左移，再叠加回原帧**：原帧保持锐利，
白平衡不变，边缘拉出红/青错位，文字仍然可读，崩坏强度却一点没减。

## 实现注意

- 全部用可移植的 Canvas2D 算子。`luminosity` 混合在 @napi-rs/canvas 上会把整帧刷成白色，
  描线闪白改用已验证的 `color` 混合。
- 需要 4 张离屏画布（原帧 / 工作层 / 暂存 / 输出），在 1080p 下约 33MB，随进程复用。
- 崩坏帧比普通帧慢约 150–250ms；崩坏只发生在约 40% 的时间轴上。
- 预览页新增"崩坏后期"开关，可与"人物特效"对照同一帧。
- HUD 右上角新增 DECONSTRUCT 计量条，按段实时显示损坏程度。

## 与阅读层的关系

崩坏作用在**整幅合成结果**上，包括阅读层与 HUD。文字会一起被撕裂、错位、去色，
这是有意的：重复段与高潮段本来就是"现实拒绝"的地方，文字失去稳定感即是叙事。
其余段落（记忆、信号、结局）完全不受影响，126 行歌词仍然可以正常阅读。
