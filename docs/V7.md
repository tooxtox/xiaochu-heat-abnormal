# 第七版：授权时间窗 + 信号式歌词排版

记录日期：2026-10-24。第七版做两件事：把第六版的崩坏后期**严格收进两个授权时间窗**，
并把歌词从"平滑的优雅字幕"改写成**终端解码式的信号排版**。

---

## 一、崩坏时间窗化

### 问题

第六版的崩坏按场景 ID 全局生效，24–35s（ERASE / PERSIST）、52–57s（WHISPER / ANOMALY）、
118–123s（TURN AWAY / HEAR）、220–226s（BROKEN VOICE / REPRISE）等段落都会出现。
用户明确要求："高潮有两段，一段是 1:08 到 1:30，一段是 3:09 以后。不要在其他地方加刚刚那些特效。"

### 做法

新增 `src/signal_windows.mjs`，作为**全片唯一的授权表**：

| 窗口 | 区间 | 底噪 floor | 歌词损坏 corrupt |
|---|---|---|---|
| `REPEAT` | 68.000 – 90.000（1:08–1:30） | .52 | .42 |
| `CLIMAX` | 189.000 – 231.690（3:09–3:51.69） | .34 | .88 |

- `glitchAt()` 的第一件事就是查这张表：**窗口外一律返回 `null`**，连降级计算都不做。
- 窗口内的强度 = `max(场景底噪, 窗口 floor)`。场景底噪沿用第六版（scene 8 = 1.00、
  scene 9 = .95、ARRIVAL / BLACK STAR 再 +.30），所以真正的峰值仍然落在
  CORE / HEAT ABNORMAL 与 ARRIVAL / BLACK STAR 上。
- 窗口边缘加 0.4 秒淡入淡出，避免硬切造成亮度突变。
- HUD 的 DECONSTRUCT 计量条跟着 `glitchAt()` 走，因此它也只在这两段出现。

### 关于第二段窗口的终点

3:09 之后到 231.690（THE LAST MESSAGE 开始）是高潮本体：CELLS → CORE / HEAT ABNORMAL →
REALITY / REFUSAL → APPROACH II → ARRIVAL / BLACK STAR。231.690–242.538 是收尾
（最后的传输与关机），原设计里本来就是干净段，因此窗口在 231.690 结束。
如果要让崩坏一直延续到片尾，只需把 `signal_windows.mjs` 里 `CLIMAX.to` 改成 242.538333。

### 实测分布

以 1/60 秒步长扫描全片 14553 帧，崩坏实际出现的区间只有：

```
68.017 – 89.983   (21.97 s, 峰值强度 1.000)
189.067 – 231.633  (42.57 s, 峰值强度 1.000)
```

其余 218 秒完全干净。

## 二、歌词排版：终端解码式

用户评价："当前歌词的风格和动画都太平滑了，和本 MV 风格不符合。可以适当增加一点卡顿感。"

### 1. 去掉连续缓动

第六版所有入场/出场都用 `smooth()`（smoothstep），文字是连续滑入连续淡出。
第七版引入阶梯曲线：

```js
function stepEase(q, steps) {          // 8 段入场 / 5 段出场
  q = clamp(q); const s = Math.max(1, steps | 0);
  return Math.min(1, Math.floor(q * s + 1e-9) / Math.max(1, s - 1));
}
```

并且整个排版锁在一个 **15Hz 信号时钟**上：`quantTime(t, 15) = floor(t×15)/15`。
所有位移、淡入淡出、路径推进都取整到该时钟，动画因此变成"逐格跳进"，而不是平滑滑动。

### 2. 逐字解码

每个字按固定节奏依次落地：

- 解码跨度 `span = min(0.62s, 段落时长 × 0.42)`，第 i 个字的解码时刻 = `起点 + i/(n-1) × span`。
- 未解码的字不绘制；`visible` 标记与绘制逻辑共用同一份数据，因此几何 QA 的
  "绘制文本 == 期望文本" 契约仍然成立。
- 显式词时间（`wordTiming: explicit`）命中时给一次**硬切强调**：
  颜色跳到 mint、字身放大 5%，0.42 秒内分 6 级衰减，不再是连续指数衰减。

### 3. 终端装饰

每个歌词块外面挂一套终端家具，全部用矩形绘制（不追加文字，避免破坏几何 QA 的文本契约）：

- **四角括号**：4 组 L 形短角，颜色取当前墨色，透明度 30%。
- **解码缓冲条**：一排最多 40 个格子，一格对应一个字，已解码的格子点亮——
  进度直接可读，是"这台机器正在把歌词解出来"的读数。

### 4. 字形处理

| | 第六版 | 第七版 |
|---|---|---|
| 描边 | 居中细描边（paper / black） | 居中细描边 + **硬边套印偏移**：深色描边整体偏移 (0.026, 0.026)×字号，模拟印刷套印歪 |
| 柔和感 | 光晕式描边 | 硬边、无光晕 |

### 5. 授权窗口内的信号损坏

与崩坏后期**共用同一张时间表**，窗口外一律不出现：

- **色散边**：红/青细描边各偏 ±0.013×字号，线宽 0.016×字号。
  描边必须比字画细，否则中文细笔画会被红青色糊成一团（实测踩过这个坑）。
- **颜色跳变**：单个字整段跳成 red 或 teal。
- **掉字**：单个字在某一格内不绘制，形成解码空洞。
- **错位**：单个字整体平移最多 ±9px。

概率按窗口损坏强度线性分配：`掉字 .030×level`、`红 .085×level`、`青 .075×level`、
`错位 .160×level`。第一处窗口 level .42（克制），第二处 level .88（明显失序）。

### 6. 背景意象动画

`src/lyric_motifs.mjs` 的 10 类意象同样锁到 15Hz 时钟并改用阶梯曲线，
入场/出场淡入淡出切成 6 段 / 4 段；授权窗口内整个意象产生一次量化位移。

### 7. 一个必须修的哈希缺陷

第六版起的 `hash(a,b) = fract(sin(a×127.1 + b×311.7) × 43758.5453)` 对**连续索引高度相关**：
相邻字号的相位每次推进 245.3 弧度，只相当于 0.04 个周期，于是整串相邻字会落在同一状态上
（实测出现连续 6 个字同时变红）。第七版把 `hash2()` 换成整数雪崩混合
（xorshift + 乘法素数），桶分布 1923–2091/2000，相邻同类最长连续 3 个。
