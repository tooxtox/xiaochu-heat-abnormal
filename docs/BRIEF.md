## 2. 核心创意：世界末日的最后一个观测者

### 故事名称

《熱異常 / LAST SIGNAL》

副标题：

**SYSTEM TEMPERATURE: CRITICAL**

### 故事梗概

在遥远的未来，地球已经进入无法逆转的异常状态。

天空逐渐变成黑红色。

月亮失去原本的颜色。

城市的灯光一盏接一盏熄灭。

通讯网络开始崩溃。

世界的温度正在持续上升。

一座已经被遗弃的巨型观测站里，只剩下一个系统仍在运行。

它的名字叫「小初」。

小初是一位薄荷绿色长发、粉色眼睛的猫耳少女。

她并非灾难的制造者，而是这个世界最后的记录者。

她不断收集数据、分析异常、发送警报，试图寻找让世界恢复正常的方法。

但是所有通讯都得不到回应。

于是她不断重复计算。

不断发送。

不断删除。

不断重新开始。

系统的温度越来越高。

她仍然不愿意停止。

随着音乐推进，她逐渐意识到：

她所试图保存的，不仅仅是这个世界的数据，还有在这个世界里曾经存在过的记忆。

整部 MV 围绕以下矛盾展开：

**一个本应精确而冰冷的系统，为什么会因为无法挽回的事物而产生无法解释的热量？**

小初既是观测者，也是最终的记录者。

她会在这场异常中逐渐失去对系统的控制，但始终没有放弃传递最后一条信息。

### 整体叙事曲线

静默观测 → 异常发现 → 恐惧 → 循环 → 世界失控 → 试图挽救 → 系统崩溃 → 最后的记录 → 寂静。

结局应该具有开放性。

不需要直接宣布小初的死亡。

应该让观众自己思考：系统是否已经停止，她是否还存在，以及最后的信号是否到达了某个人的手中。

- 名字：小初（Xiaochu）

- 外貌年轻、软萌、清秀
- 薄荷绿色长发
- 两只薄荷绿色猫耳
- 一条猫尾巴
- 粉红色眼睛

- 线条柔和，整体造型清新

不要将小初改成其他角色。

不要擅自将她变成银发、黑发、红眼、机械怪物或成熟御姐。

即使系统失控，她仍然是小初。

- 恐惧

- 强烈情绪

- 裙摆漂浮

使用分层角色资源或有限动画技术实现。

如果缺少必要素材，记录具体需求，不要使用不符合人设的图片代替。

## 5. 三种画面类型

### A：观测界面

这是小初看到的世界。

由代码绘制：

- 温度曲线
- 传感器读数
- 天体观测图
- 世界地图
- 城市状态
- 通讯日志
- 终端窗口
- 系统错误
- 时钟
- 数据流
- 监控画面
- 波形
- 频谱
- 模拟仪表
- 目标检测框
- 坐标标记

所有数据是服务于剧情的虚构数据，不能假装是真实环境测量。

每个 UI 元素都必须具有明确的信息作用。

### B：人物与世界

包含小初的完整角色画面。

场景包括：

- 巨大的观测站
- 空无一人的控制室
- 暗红色天空
- 废弃城市
- 崩塌建筑
- 黑色太阳
- 被异常热量扭曲的云层
- 无人的街道
- 被遗忘的房间
- 充满静电噪声的通讯设施

角色不能只是放在画面中央。

要通过场景、构图、空间和镜头运动呈现小初与这个世界的关系。

### C：抽象图形与歌词空间

当音乐进入剧烈变化的段落，画面脱离现实。

使用：

- 几何递归
- 数字瀑布
- 图形分裂
- 巨大文字
- 字符旋转
- 频谱粒子
- 向量场
- 破碎网格
- 错位印刷
- 圆形仪表
- 热量波纹
- 字符构成的人物剪影
- 由公式逐步生成的图形
- 文字形成的螺旋与隧道

这些特效不能只是随机运动。

每种特效必须与歌曲的节拍、歌词含义或剧情事件直接关联。

# 6. 完整 MV 分镜规划

以下是剧情镜头的创意要求。

**具体时间必须根据真实歌曲音频和歌词分析确定，不能将以下章节机械分成等长片段。**

## Scene 01：INIT / 系统启动

黑屏。

显示一个极细的薄荷绿光标。

终端缓慢输入：

`INITIALIZING...`

`OBSERVER: XIAOCHU`

`STATUS: ONLINE`

第一声音乐响起。

黑色画面出现少量颗粒。

随后一根细线将屏幕一分为二。

画面出现巨型观测站的内部。

所有显示器都熄灭了。

只有一台终端在运行。

镜头缓缓推进。

小初坐在电脑前。

她低着头，薄荷绿长发垂落在肩膀上。

终端微弱的光映在她粉色的眼睛里。

她缓缓抬起头。

第一句歌词开始时，屏幕正式亮起。

## Scene 02：DEAD VARIABLES / 无效变量

大量变量从画面两侧流入。

出现递归结构与损坏的数据表。

数据不断变化，但最终始终返回相同的数值。

小初试图修改程序。

每次修改之后都会自动恢复。

设计一个连续变形的环状几何图案。

圆环每旋转一次，就产生更多错误。

画面分为多个终端窗口。

窗口逐渐向观众逼近。

歌词可以嵌入变量流中，随人声依次浮现。

## Scene 03：TEMPERATURE RISING / 热量上升

观测站发出第一次警报。

温度曲线突然向上偏移。

橙色第一次进入画面。

小初的猫耳轻轻颤动。

她看向正在变化的监控屏幕。

原本正常的城市画面开始出现局部异常。

天空中出现一条不自然的黑色裂缝。

画面通过数据图和城市天际线进行匹配剪辑。

一条代表热量的橙色曲线逐渐变成城市上方的红色弧线。

温度读数不断增加，但不能无意义地堆叠随机数字。

## Scene 04：DELETE LOOP / 删除循环

音乐中的快速重复结构触发大规模歌词与字符动画。

画面变成纯粹的命令行空间。

巨大文字依次出现：

`DELETE`

`RETRY`

`DELETE`

`RETRY`

文字伴随音乐重音出现和移位。

小初站在画面中心。

四周悬浮着无数重复的控制窗口。

窗口不断被关闭，又不断重新打开。

每轮循环后，人物周围增加一层细微的图形偏移。

到该段最后一次重复时，所有文字迅速向画面中心聚集。

随后突然消失。

画面只留下小初。

她抬头看向一块空白屏幕。

不要通过高频全屏闪白来实现这段高潮。

优先使用位移、运动模糊、缩放、排版和节奏变化。

## Scene 05：BLACK STAR / 黑色恒星

观测系统检测到一个异常天体。

屏幕中央出现黑色圆形。

起初只是一个小点。

随着音乐推进逐渐放大。

小初伸出手，试图接触它。

黑色圆形内部出现复杂的程序化纹理。

外部环绕着不断变化的轨道、坐标、光线和公式。

它的中心不发光，而是吞没周围的颜色。

巨大的黑色天体逐渐占据整个画面。

小初的粉色眼睛里映出它的轮廓。

镜头从她的瞳孔切入黑色天体内部。

画面进入下一段。

## Scene 06：THE FALL / 城市崩溃

镜头从天体内部穿出。

整个世界已经发生改变。

天空变为暗红。

远处城市的轮廓正在崩坏。

高楼变成不规则的几何碎片。

电线杆和建筑阴影拉长。

道路上的裂缝逐渐扩散。

风把小初的长发吹起。

她独自站在城市的高处。

摄像机从低角度环绕她。

镜头越过她的肩膀，看到远处不断扩大的异常。

歌词采用巨大的纵向日文排版。

文字从建筑物之间上升。

城市中的每一次破坏，都应对应音乐的明确事件。

## Scene 07：LAST MEMORY / 最后的记忆

音乐进入情绪较为内敛的部分。

画面开始降低运动强度。

小初回到观测站。

她打开一个旧文件夹。

里面是这个世界恢复正常之前留下的记录。

画面出现短暂的回忆：

- 阳光照射的窗台
- 蓝色天空
- 温柔的风
- 小初轻轻摆动的猫尾
- 一朵被保存下来的小花
- 曾经明亮的城市

回忆中的世界以薄荷绿、粉色和白色为主。

画面边缘仍带有轻微的数据损坏。

小初看向这些记忆。

第一次露出真正悲伤的表情。

她伸出手。

一朵由数据构成的小花落在手心。

它逐渐散成无数光点。

这一段不要使用过度的故障效果。

把安静与细腻留给人物。

## Scene 08：RUNAWAY / 热失控

系统检测到不可逆的异常。

镜头快速接近小初的眼睛。

粉色虹膜中出现旋转的黑色天体。

监控画面、歌词、热量曲线、图形、错误日志同时发生变化。

设计全片第一次真正的大规模热失控。

重要视觉事件：

1. 观测站灯光逐级转红。
2. 温度曲线穿过临界线。
3. 大量终端窗口从背景中展开。
4. 小初的剪影出现错位。
5. 图形结构开始递归分裂。
6. 天空中的黑色天体快速扩大。
7. 所有数据汇聚到小初的身后。
8. 整个画面在音乐强拍上形成巨大的红色警告构图。

终端显示：

`THERMAL RUNAWAY`

`CORE STATUS: CRITICAL`

`RECOVERY FAILED`

小初站在画面中央。

所有图形都在旋转、移动、压缩。

但是人物本身必须保持可以辨认。

**这段是系统失控，不是人物造型失控。**

不能因为追求视觉震撼把小初扭曲成其他角色。

## Scene 09：REALITY ERROR / 现实错误

高潮进一步推进。

使用强烈的动态文字、画面撕裂、剪影错位和递归图形。

文字随实际人声分组出现。

不能整句歌词提前铺满屏幕。

场景中的物理规律逐渐失效。

建筑变成平面图形。

地面折叠成网格。

星空反转成黑色。

小初逐渐漂浮起来。

她的长发向四周散开。

无数文字碎片从她身旁掠过。

她试图向前伸手。

画面中出现一个微弱的薄荷绿色光点。

周围的红色不断向中心挤压。

她却始终盯着那一束光。

这个镜头的情感核心不是恐怖，而是不甘心。

## Scene 10：THE LAST MESSAGE / 最后的信息

音乐逐渐接近最终段落。

所有系统画面开始失去响应。

小初坐回终端前。

她的动作变慢。

镜头从远景逐渐推进到脸部特写。

终端中只剩下一条尚未发送的记录。

小初抬起头。

粉色眼睛里反射着微弱的薄荷绿色光芒。

她伸出手，按下最后一次发送指令。

镜头切换为广阔的黑色宇宙。

一束细小的绿色信号从崩溃的星球表面飞出。

信号穿过无数星星。

周围只剩下近乎完全静止的宇宙。

在最后一个重要音乐事件处，绿色信号突然扩散成一朵由细线和字符组成的巨大花朵。

随后慢慢消失。

## Scene 11：SHUTDOWN / 寂静

终端恢复为最初的画面。

但房间里已经没有任何动作。

控制室的灯一盏接一盏熄灭。

镜头缓慢移动到小初原本站立的位置。

那里只剩下一点薄荷绿色的光。

画面逐渐缩小成一条记录文件。

最后显示：

`OBSERVER: XIAOCHU`

`LAST SIGNAL: SENT`

`RESPONSE: UNKNOWN`

不要显示确定的死亡结论。

屏幕渐渐变暗。

最后一个薄荷绿色光标闪烁一次，然后静止。

画面变黑。

歌曲结束。

## 7. 动态歌词系统

这是技术制作的核心。

《熱異常》具有密集的人声与大量快速重复的词句，因此不能使用普通的整行歌词淡入淡出。

要求开发完整的日文动态歌词系统。

每条歌词的时间必须来自真实 LRC 或对齐数据。

对于快速重复的段落，必须尽可能进行字级或词级对齐。

设计多种文字表现形式：

- 极速逐字显示
- 文字错位
- 巨大单词冲击
- 矩阵式重复
- 字符切割
- 旋转文字
- 弯曲路径文字
- 文字递归
- 文字构成剪影
- 纵向排版
- 文字与人物前后遮挡
- 文字被吸入黑色天体
- 文字粒子化

正常段落的字幕需要完整可读。

高速段落可以使用辅助动态文字增强冲击，但至少应保留可靠、清晰、完整的歌词阅读层。

重要歌词跟随实际人声起音。

鼓点负责画面次级反应。

不得为了踩鼓点而让重要文字明显提前或延迟。

歌词必须从本地文件读取。

不要硬编码整首受版权保护的歌词。

## 8. 音频分析要求

使用真实音频分析确定：

- BPM 与节拍网格
- 小节起点
- 人声起音
- 频谱能量
- 低频鼓点
- 高频瞬态
- 响度曲线
- 音乐段落
- 情绪高潮位置

自动分析只能生成候选时间点。

最终镜头与关键词时间需要经过检查。

建立统一的 `cues.json`。

重要事件集中管理，不允许把大量未经校正的时间数字分散写入不同场景文件。

建立可视化音频波形与镜头时间轴。

支持逐帧检查同步。

## 10. 视觉效果设计规则

### 光效

不要全程使用最大 Bloom。

正常镜头的辉光应当很弱。

异常段落可以逐渐增强。

最终高潮才使用高亮度光线与复杂后处理。

### 故障动画

故障应该与系统状态和音乐事件相关。

允许出现：

- 短暂 RGB 分离
- 图层错版
- 水平撕裂
- 字符损坏
- 马赛克
- 数据块丢失
- 帧内重复
- 图形错位
- CRT 扫描线

但必须保证人物面容保持可识别。

不得连续制造让人不适的大面积高速闪烁。

### 镜头运动

使用：

- 缓慢推近
- 快速拉远
- 跟随运动
- 环绕镜头
- 视差
- 镜头旋转
- 连续推入
- 图形匹配剪辑
- 前景遮挡转场
- 跟随歌词运动的镜头

快速运动需要适当的运动模糊。

不能让整部 MV 只是平面图片反复缩放。

### 画面构图

必须交替使用：

- 超大远景
- 人物中景
- 人物半身
- 面部特写
- 眼睛特写
- 手部特写
- 全屏文字
- 纯图形镜头
- 终端界面镜头

不同镜头应具有鲜明的视觉节奏。

## 12. 开发顺序

### 第一阶段：制定视觉与时间计划

检查素材与音频。

读取参考项目中的制作文档。

分析真实歌曲。

设计分镜。

输出 `PLAN.md` 与 `STORYBOARD.md`。

### 第二阶段：制作核心系统

实现时间轴、程序化图形、文字动画、角色渲染、音频同步和场景转换。

先制作三类测试镜头：

1. 小初在观测站的角色镜头。
2. 复杂动态歌词与终端循环镜头。
3. 黑色天体与热异常高潮镜头。

验证视觉效果后扩展到整部歌曲。

### 第三阶段：制作全部场景

每完成一个镜头：

- 检查第一帧。
- 检查主事件帧。
- 检查结束帧。
- 检查文字位置。
- 检查人物外观。
- 检查帧间运动。
- 检查音乐同步。

生成镜头缩略图并记录结果。

### 第四阶段：全片精修

重点检查：

- 动态歌词可读性
- 小初的角色一致性
- 颜色随剧情改变
- 黑色恒星的视觉重量
- 热量异常的表现
- 故障效果节奏
- 重大镜头切点
- 结局的安静感

### 第五阶段：导出与交付

最终必须交付：

- 全部可运行源代码
- 本地预览界面
- 完整分镜表
- 1080p60 MP4
- 关键镜头预览图
- 音画同步检测
- 闪光安全检测
- 角色素材使用说明
- 尚未完成部分的说明

不要伪造已经通过的测试或已经生成的成片。

## 13. 最终导演要求

我不要一部只有程序终端与滚动字幕的普通技术展示。

我也不要一部只有小初静态立绘、粒子背景和几段故障特效的简单视频。

**小初必须真正成为故事的中心。**

观众应该能看到她从冷静观测、发现异常，到恐惧、坚持、失控和最终平静的完整情绪变化。

画面应该具有强烈的艺术表现力：

平静时安静得令人不安。

异常时具有不断积累的压迫感。

高潮时充满复杂却有秩序的视觉变化。

结尾时让所有声音与图形的重量突然消失。

整个 MV 应当让人感受到：

> 世界的温度不断上升。
>
> 变量可以被删除，数据可以被覆盖。
>
> 但有些东西，无论重复多少次，都无法彻底消除。
>
> 在最后一次系统崩溃之前，小初仍然试图留下自己的声音。

最后请牢记：

**这不是小初被世界毁灭的故事，而是一个关于记录、记忆和存在的故事。**

现在开始检查工程目录与素材，读取参考项目，分析歌曲，制定实际的时间轴，并逐步完成可以运行、预览和导出的完整 MV。

不要只给我设计思路，请直接开始编写和测试工程。
